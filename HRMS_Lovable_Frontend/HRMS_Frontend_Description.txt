

Google Sheet:

- 2 sheets: 'Clients' and 'Campaigns'

- 'Clients' sheet columns: 
[Client ID, Client Name, Client Email, Client Phone, Chat ID, Date, Time, Chat Text, 
Client Type, Client Interests, Client Traits, Client Category]

- 'Campaigns' sheet columns: 
[Campaign ID, Campaign Text, Target Client Category, Start Date-Time, End Date-Time, Target Customers Count, 
Campaign Message Count, Campaign Status, 
Message Template #1, Message Send Timing #1, Message Template #2, Message Send Timing #2, Message Template #3, Message Send Timing #3]



Frontend Goal:
- Main purpose it to fill Marketing Campaigns information in Google sheet.
- There should be Register/Login option.
- Only Logged in person should be able to do that.
- A single page upon logging in can show all options to fill a new campaign data.

- Fill data in 'Campaigns' sheet columns: 
[Campaign Text, Target Client Category, Start Date-Time, End Date-Time, Campaign Message Count,
Message Template #1, Message Send Timing #1, Message Template #2, Message Send Timing #2, Message Template #3, Message Send Timing #3]

- Design Style: Modern and Suitable for Marketing teams.

Framework: React + Vite

Backend API: 
- Google Apps Script

Core interactions:
- It needs to interact with App Script, so the app script can further update the relevant fields in 'Campaigns' sheet.

Special features:
- Campaign Text, Message Template #1/2/3 can be an edit box.
- Target Client Category should be a dropdown, with options like Solo, Family, Business.
	- Category Options can be added/removed/updated as well as per requirements.
- Start Date-Time, End Date-Time can be appropriate and convenient date-time settings.
- Message Send Timing #1/2/3 should be only time settings.
- Campaign Message Count can be a number input with a range between 0 to 10.



































Build a React + Vite frontend for an HRMS Marketing Campaign Manager.
The app connects to a Google Apps Script backend that updates a Google Sheet with two sheets:
Clients and Campaigns.



🧩 Functional Goals:

1. Provide Register/Login functionality (simple email-password form, local storage for auth simulation).

2. After login, show a single page dashboard for adding or editing Campaigns.

3. This dashboard should collect data for these columns in the “Campaigns” sheet:
	- Campaign Text (multi-line textbox)
	- Target Client Category (dropdown: Solo, Family, Business)
	- Start Date-Time (calendar/time picker)
	- End Date-Time (calendar/time picker)
	- Campaign Message Count (numeric input 0–10)
	- Message Template #1, #2, #3 (multi-line text areas)
	- Message Send Timing #1, #2, #3 (time pickers only)

4. On form submit, the frontend must POST JSON to a configurable backend API endpoint (stored in .env):
	{
	  "campaignText": "...",
	  "targetClientCategory": "...",
	  "startDateTime": "...",
	  "endDateTime": "...",
	  "campaignMessageCount": 5,
	  "messageTemplate1": "...",
	  "messageTiming1": "...",
	  "messageTemplate2": "...",
	  "messageTiming2": "...",
	  "messageTemplate3": "...",
	  "messageTiming3": "..."
	}

5. The backend (Google Apps Script) will handle writing this data to the Campaigns sheet.




🧱 Technical Requirements:

- Use React + Vite setup.

- Use TailwindCSS + ShadCN/UI for modern styling.

- Create reusable components for:
	- LoginForm
	- CampaignForm
	- Header / Navbar

- The API endpoint URL and API key must come from .env as VITE_CAMPAIGN_API_URL and VITE_API_KEY.

- Show success/failure toast notifications after submission.

- Keep the layout responsive and clean (suitable for marketing teams).

- Include basic validation (no empty required fields).




🎨 Design Style:

- Professional, HR marketing-oriented, modern colors.

- Simple top navigation (e.g., HRMS logo + “New Campaign”).

- Centered form card with soft shadows and rounded corners.

- Use Tailwind typography and grid layouts for spacing.




🧩 Notes:

- Do not build the backend — just connect to it using fetch() from import.meta.env.VITE_CAMPAIGN_API_URL.

- Assume backend already supports CORS and accepts POST requests.

- Provide placeholder .env template in the generated project root.

- Final deliverable: fully working React frontend that can submit campaigns via the configured API.
